# Спецификация: планирование закупок импортёра

## Задача

Закупщик импортёра (электроинструмент, сад, сантехника из Китая, плечо 4–6 месяцев)
каждый месяц решает, что и сколько заказать. Надо держать в голове историю продаж,
сезон, остатки, заказы в пути и ненадёжность поставщиков — это долго, и ошибка видна
только через полгода: либо дыра на складе в сезон, либо замороженные деньги.

## Решение

Одна команда читает выгрузку ERP и выдаёт статичный дашборд: что заказать сейчас,
что запланировать и на какую дату, где будет дефицит, где избыток, какой товар
не закупать из-за наценки или потому что он мёртвый. Все цифры считает
детерминированный код; модель только объясняет готовые цифры словами. Повторный
запуск по свежей выгрузке показывает, что изменилось с прошлого раза.

## Решения по реализации

- **Python ≥ 3.11, pandas + numpy, pytest.** На машине только 3.11; возможностей 3.12 не нужно.
- **HTTP к модели — `urllib` из стандартной библиотеки**, формат OpenAI `/chat/completions`. Лишняя зависимость не нужна.
- **`.env` читается своим маленьким разбором** (строки `KEY=VALUE`), переменные окружения главнее файла. Без `python-dotenv`.
- **Дашборд — один HTML**, шаблон в `zakupki/templates/dashboard.html`, данные подставляются JSON-блоком; таблица на чистом JS; Plotly `2.35.2` с cdnjs.
- **σ в страховом запасе — разброс месячного спроса вокруг сезонного прогноза**, а не сырой σ продаж: у обогревателя сырой σ — это сама сезонность, и страховой запас вышел бы больше годовых продаж. Отклонение от буквы брифа сознательное, строка в отчёте.
- **Имена порогов:** в тексте спецификации — по смыслу, в коде — поля `Config` в нижнем регистре (`min_markup_pct`, `z`, `default_cover_days`, `llm_batch` …), список — `interfaces.md`.
- **Даты — помесячные корзины**, внутри месяца — линейная интерполяция для дня обнуления; 1 месяц = 30.4 дня.
- **Надёжность по формуле брифа.** В данных 328 из 383 `closed` заказов с `qty_received = 0` — похоже на отменённые; формула брифа их учитывает, общая надёжность ≈ 0.39. Делаем как в брифе, в сводке — строка об этом.
- **Кэш модели** — JSON рядом с выходом, ключ — хэш промпта.
- `out/` не коммитится; публикация — workflow собирает заново.
