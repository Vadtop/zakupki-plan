## Что должно заработать

`build_plan(...)` собирает итог закупки: по каждому SKU — сколько заказать, основной статус
и флаги, отдельно потребность у товаров, которые в автозакупку не идут; таблицу рисков
(дефицит, избыток, просроченные заказы, «распродать»); календарь заказов на 12 месяцев.
Симуляцию, покрытие и даты уже считает `zakupki/simulation.py` (таск 04a) — бери их оттуда.

~400–500 строк вместе с тестами. `simulation.py`, `demand.py`, `forecast.py`, `supply.py` не меняй —
нашёл в них ошибку → опиши в `CONCERNS`. `tests/conftest.py` не меняй.

## Из брифа, дословно

> «**Сколько.** Прогноз на (плечо + период покрытия) + страховой − остаток −
> в пути (с надёжностью). Период покрытия: `target_cover_days`, если > 0, иначе 90 дней.
> Не меньше 0, округлить вверх; если есть кратность партий по `receipts` — до неё.»

> «Повторно уже заказанное не заказывать.»

> «**Статусы SKU** (у каждого ровно один основной + флаги):
> - `ЗАКАЗАТЬ СЕЙЧАС` — дата заказа ≤ сегодня + 30 дней;
> - `ЗАПЛАНИРОВАТЬ` — дата заказа в пределах 12 мес;
> - `ЗАПАС В НОРМЕ`;
> - `РИСК ДЕФИЦИТА` — обнулится раньше, чем успеет прийти заказ, сделанный сегодня
>   (докупить не успеваем: показать, сколько месяцев «дыры»);
> - `ИЗБЫТОК` — покрытие > плечо + покрытие + 6 мес (заморожены деньги);
> - `НИЗКАЯ НАЦЕНКА` — `avg_markup_pct_12m` < `MIN_MARKUP_PCT=25`: **в автозакупку
>   не попадает**, отдельный список «пересмотр цены / вывод»;
> - `МЁРТВЫЙ` — нет продаж 12 мес (пустая наценка): не закупать, отдельный список,
>   если есть остаток — «распродать»;
> - флаг `МАЛО ИСТОРИИ`.»

> «С `promised_date` в прошлом — «просрочен» … и вывести в рисках.»

> «Тесты pytest на ключевую логику: … заказы в пути не заказываются повторно, низкая наценка
> не попадает в автозакупку, мёртвые распознаются, просроченный заказ уходит в риски, детерминизм.»

## Разделы спецификации

Истории 17, 22–29, 31, 41 (календарь — данные). Границы — `interfaces.md`: раздел `zakupki/plan.py`
(колонки `plan` и `risks` ровно в этом порядке, `PlanResult`), `zakupki/simulation.py` (что берёшь),
`STATUS_ORDER` в `config.py`.

Количество для SKU с датой заказа `order_date` (для ЗАКАЗАТЬ СЕЙЧАС и РИСК ДЕФИЦИТА — с `today`):
`forecast_between(order_date, order_date + lead + cover)` + `safety_stock` − `projected_stock(order_date)` −
`arrivals_after(order_date)`, не меньше 0, вверх до целого, потом до кратного `lot_size`. Это `need_qty`;
`order_qty` = `need_qty` только у ЗАКАЗАТЬ СЕЙЧАС, РИСК ДЕФИЦИТА, ЗАПЛАНИРОВАТЬ, у остальных 0.

## Критерии приёмки

- [ ] `plan` — одна строка на каждый SKU из `sku_dim`, колонки ровно из `interfaces.md` в том же порядке; сортировка по `STATUS_ORDER`, `order_date`, `sku_id`
- [ ] Тест: открытый заказ, покрывающий потребность (с надёжностью), → `order_qty = 0`
- [ ] Тест: `need_qty` по формуле на ручном примере; кратность партии 200 и потребность 450 → 600
- [ ] Тест: наценка < 25 → НИЗКАЯ НАЦЕНКА, `order_qty = 0`, `need_qty > 0`
- [ ] Тест: пустая наценка → МЁРТВЫЙ, `order_qty = 0`; с остатком > 0 — строка в `risks` с пометкой «распродать»
- [ ] Тест: `gap_months > 0` → РИСК ДЕФИЦИТА, `order_qty` посчитан от today, строка в `risks` с `gap_months`
- [ ] Тест: покрытие > плечо + покрытие + `excess_extra_months` → ИЗБЫТОК, `order_qty = 0`, в `risks` с лишними месяцами
- [ ] Тест: дата заказа ≤ today + 30 → ЗАКАЗАТЬ СЕЙЧАС; в пределах 12 мес → ЗАПЛАНИРОВАТЬ; иначе ЗАПАС В НОРМЕ
- [ ] Тест: просроченный открытый заказ → строка `risks` с `risk_type = ПРОСРОЧЕН ЗАКАЗ`, `po_id`, `promised_date`, `qty`
- [ ] Тест: один основной статус, остальные сработавшие — в `flags` через «; », плюс `МАЛО ИСТОРИИ`
- [ ] `calendar`: 12 месяцев от месяца today, `positions` и `qty` для ЗАКАЗАТЬ СЕЙЧАС / РИСК ДЕФИЦИТА / ЗАПЛАНИРОВАТЬ; прошедшая дата заказа — в текущем месяце (тест)
- [ ] Тест детерминизма: два вызова → побайтно одинаковый `plan.to_csv()`
- [ ] Порогов-чисел в коде нет, только поля `Config`
- [ ] Проверка зелёная: `python3 -m ruff check zakupki tests && python3 -m pytest -q`
