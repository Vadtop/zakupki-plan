# 04a — Симуляция запаса, покрытие, дата обнуления и дата заказа

**Требования:** R03, R04, R11, R18, R20, R21, R25, R50
**Зависит от:** 02, 03
**Зона:** `zakupki/simulation.py` · `tests/test_simulation.py`
**Волна:** 3
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

`run_simulation(...)` из остатка на сегодня, прогноза и заказов в пути помесячно
проигрывает запас каждого SKU: на сколько дней и месяцев его хватит, когда он обнулится,
какой нужен страховой запас и до какой даты разместить следующий заказ. Если запас кончится
раньше, чем успеет прийти заказ, сделанный сегодня, — сколько месяцев «дыры». Плюс три помощника,
которые таск 04b возьмёт для расчёта количества.

~350–450 строк вместе с тестами. Количества, статусы, риски и `plan.py` — не здесь, это таск 04b.
`demand`, `forecast`, `supply` уже есть — вызывай, не меняй. `tests/conftest.py` не меняй.

## Из брифа, дословно

> «**Симуляция запаса** помесячно на 12 мес: остаток − прогноз + приходы по датам.
> Отсюда: на сколько месяцев/дней хватит (покрытие с учётом заказов в пути),
> месяц обнуления.»

> «**Когда заказывать.** Дата = дата обнуления − плечо − страховой запас.
> Страховой запас: `z=1.65` × σ месячного спроса × √(плечо в мес.).»

> «`РИСК ДЕФИЦИТА` — обнулится раньше, чем успеет прийти заказ, сделанный сегодня
> (докупить не успеваем: показать, сколько месяцев «дыры»)»

> «Заказы в пути учитываются с этим коэффициентом.» «С `promised_date` в прошлом — «просрочен»,
> считать, что придёт через 30 дней»

> «Один и тот же вход → один и тот же план.»

## Критерии приёмки

- [ ] `run_simulation` возвращает `positions` (колонки ровно из `interfaces.md`, одна строка на SKU) и `sim` (`cover_horizon_months` месяцев на SKU)
- [ ] Тест: ровный спрос 30/мес, остаток 90, без приходов, today = 1-е число → обнуление через ~3 мес, `cover_days` ≈ 91, `cover_months` ≈ 3
- [ ] Тест: в месяце today вычитается только оставшаяся доля прогноза (today = 16-е → примерно половина месяца)
- [ ] Тест: приход `expected_qty` в месяц `expected_date` отодвигает обнуление; просроченный заказ (expected_date = today + 30) учитывается в следующем месяце
- [ ] Тест: `safety_stock = z × sigma × √(lead/30.4)` на ручном примере; sigma 0 → 0
- [ ] Тест: `order_date = stockout_date − lead_days − safety_days` на ручном примере
- [ ] Тест сезонности: обогреватель с пиком в октябре, плечо ~150 дн., today = 1 февраля → `order_date` в марте–июле; SKU с ровным спросом того же годового объёма и тем же остатком → иная дата
- [ ] Тест: обнуление раньше today + плечо → `gap_months > 0`; иначе 0
- [ ] Тест: SKU, не обнуляющийся за `cover_horizon_months`, → `stockout_date` и `order_date` = NaT, `cover_days` = дни до конца горизонта
- [ ] Тесты помощников `projected_stock`, `forecast_between` (неполные месяцы долей), `arrivals_after`
- [ ] Тест детерминизма: два вызова → равные DataFrame
- [ ] Порогов-чисел в коде нет, только поля `Config`
- [ ] Проверка зелёная: `python3 -m ruff check zakupki tests && python3 -m pytest -q`
