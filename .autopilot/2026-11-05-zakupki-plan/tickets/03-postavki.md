## Что должно заработать

По каждому SKU известно плечо поставки в днях, по каждому поставщику — доля реально
поставленного, по каждому открытому заказу — когда и сколько ожидаемо придёт (просроченные
помечены), по каждому SKU — кратность партии и остаток на дату расчёта.

~400–500 строк с тестами. `tests/conftest.py` не меняй — свои фикстуры в своём тест-файле,
фабрика `make_dataset` из conftest. Параллельно с тобой таск 02 пишет `demand.py` и `forecast.py` — их не трогай.

## Из брифа, дословно

> «**Плечо по SKU.** Медиана `planned_lead_days` по заказам этого SKU, иначе —
> поставщика (`supplier_dim`), иначе 123 дня. Ограничить 30…210.»

> «**Надёжность поставщика.** Доля поставленного: `qty_received / qty_ordered`
> по закрытым и исполненным заказам. Заказы в пути учитываются с этим
> коэффициентом. Показать в дашборде.»

> «**Заказы в пути.** `status=open`, `qty_pending > 0`. С `promised_date` в прошлом —
> «просрочен», считать, что придёт через 30 дней, и вывести в рисках.»

> «… если есть кратность партий по `receipts` — до неё.»

## Разделы спецификации

Истории 13–16, 18, 23; «Решения по реализации» (надёжность по формуле брифа).
Границы — `interfaces.md`: `zakupki/supply.py`.

Подсказки по данным (проверь сам): `planned_lead_days` бывает отрицательным (мин −13);
328 из 383 `closed` заказов с `qty_received = 0` → общая надёжность ≈ 0.39 — формулу брифа не менять;
нулевых остатков в `stock_monthly.csv` нет — нет строки = 0.

## Критерии приёмки

- [ ] Тест `lead_days`: медиана положительных `planned_lead_days` по SKU; нет заказов — `median_planned_lead_days` поставщика; нет и его — `lead_default_days`; результат всегда в `lead_min_days..lead_max_days`; отрицательные не участвуют
- [ ] Тест `supplier_reliability`: Σreceived/Σordered по `closed`+`completed`; поставщик без таких заказов — общая по всем
- [ ] Реальные данные с `today = 2026-08-13` (тест, пропуск без папки): общая надёжность в 0.35–0.45; открытых с `qty_pending > 0` — 31 заказ на 20 039 шт.
- [ ] Тест `open_orders`: только `open` с `qty_pending > 0`; `expected_qty = qty_pending × надёжность`; `promised_date < today` → `overdue=True`, `expected_date = today + overdue_shift_days`
- [ ] Тест `lot_size`: приходы 200/400/600 → 200; меньше `lot_min_receipts` приходов → 1
- [ ] Тест `current_stock`: остаток на 1-е число месяца `today` − спрос с 1-го по `today` (неполный месяц продаж) + приходы с 1-го по `today`, не меньше 0; нет строки остатка → 0
- [ ] Порогов-чисел в коде нет, только поля `Config`
- [ ] Проверка зелёная: `python3 -m ruff check zakupki tests && python3 -m pytest -q`
