**Требования:** R11, R12, R13, R14, R15, R50
**Зависит от:** 01
**Зона:** `zakupki/demand.py` `zakupki/forecast.py` · `tests/test_demand.py` `tests/test_forecast.py`
**Волна:** 2
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

Из `Dataset` получается помесячный спрос каждого SKU (продажи минус возвраты, упущенные месяцы
помечены), по категориям — сезонный индекс, по каждому SKU — уровень, тренд, σ и прогноз
помесячно вперёд. Это то, против чего потом считается закупка.

~500–700 строк с тестами. `tests/conftest.py` не меняй — свои фикстуры держи в своих тест-файлах,
пользуйся фабрикой `make_dataset` из conftest. Параллельно с тобой таск 03 пишет `zakupki/supply.py` — его не трогай.

## Из брифа, дословно

> «**Спрос ≠ продажи.** Месяц с нулевыми продажами при нулевом остатке на начало
> месяца (с 2024-01, где есть остатки) — упущенный спрос: не ноль, а пропуск,
> восполняется по сезонному профилю. Спрос = `qty_sold − qty_returned` (не меньше 0).
> Неполный месяц отбрасывается.»

> «**Прогноз с сезонностью.** Сезонный индекс по категории (по всем полным годам),
> уровень SKU — по последним 12 полным месяцам, очищенным от сезонности; тренд —
> сглаженный, с ограничением. Горизонт — 12 месяцев вперёд, помесячно. Для SKU
> с короткой историей (< 12 мес) — индекс категории + среднее за то, что есть,
> с пометкой «мало истории».»

> «Цифры считает детерминированный код (pandas). … Один и тот же вход → один и тот же план.»

> «Тесты pytest на ключевую логику: упущенный спрос, сезонность …, детерминизм.»

## Разделы спецификации

Истории 5–12, 21 (только σ), 31; «Решения по реализации» (σ — разброс вокруг сезонного прогноза).
Границы — `interfaces.md`: `zakupki/demand.py`, `zakupki/forecast.py`.

Подсказки по данным (проверь сам): в `stock_monthly.csv` нулевых остатков нет — нет строки за месяц
≥ 2024-01 = остаток 0; у 355 строк `qty_returned > qty_sold`.

## Критерии приёмки

- [ ] `build_demand`: колонки ровно из `interfaces.md`; спрос = max(0, sold − returned); `partial_month=1` и месяц `today` отсутствуют (тест)
- [ ] Тест: SKU с нулём продаж в месяцы, где строки остатка нет (≥ первого месяца снимков), — `lost=True`, `demand=NaN`; до первого месяца снимков нули — честные нули
- [ ] `seasonal_index` считается по полным календарным годам; индекс по категории в среднем 1, `share` в сумме 1 (тест)
- [ ] Реальные данные с `today = 2026-08-13` (тест, пропуск без папки): `space_heaters` — максимум индекса в октябре, май–август < 0.15; `sanitary_faucets` — все 12 в 0.6–1.4
- [ ] Тест: упущенные месяцы не занижают уровень — SKU с тремя `lost` месяцами получает тот же уровень (±5%), что без них
- [ ] Тест: обогреватель с продажами только в сезон получает ненулевой уровень; месяцы с индексом < `min_season_index` в уровень не идут
- [ ] Тест: тренд при удвоении продаж не выше `trend_max`, при падении не ниже `trend_min`
- [ ] Тест: SKU с историей < 12 полных месяцев — `short_history=True`, тренд 1
- [ ] `forecast` даёт `cover_horizon_months` строк на SKU, начиная с месяца `today`; прогноз = уровень × индекс × тренд
- [ ] Тест детерминизма: два вызова на одном входе дают равные DataFrame
- [ ] Порогов-чисел в коде нет, только поля `Config`
- [ ] Проверка зелёная: `python3 -m ruff check zakupki tests && python3 -m pytest -q`
