## Что должно заработать

Одна команда `python -m zakupki run --data data/raw/share --today 2026-08-13` даёт
закупщику `out/dashboard.html` — один файл, открывается двойным щелчком: сверху сводка
плана словами, шапка с числами, таблица «Что заказать» с сортировкой/фильтрами/поиском/CSV,
календарь заказов на 12 месяцев, риски, поставщики с надёжностью, списки низкой наценки
и мёртвого ассортимента, график по клику на SKU, сезонность категорий и блок «что изменилось
с прошлого запуска». Пояснения пишет модель через OpenAI-совместимый API, а без ключа —
шаблон из цифр. Каждый запуск сохраняет снимок в `out/history/<дата>/`. Есть скрипт для
Планировщика Windows, пример cron, workflow GitHub Actions, README, `CLAUDE.md` и навык
`.claude/skills/plan-zakupok/` — это часть сдаваемого результата: для видео, по-русски, без воды.

Расчёт из тасков 01–05 не меняется: `plan.py`, `forecast.py` и др. не трогать, кроме
вызовов из `cli.py`. Сначала прочитай раздел «Что построили законченные таски» в `interfaces.md`.

## Из брифа, дословно

> «**Дашборд** (ссылка) — наглядно: что заказать, сколько и когда; полная картина
> предстоящих закупок, чтобы принять решение.»

> «**Видео** (пишет Вадим) — инструмент, структура проекта, `CLAUDE.md`, Skills,
> промпты. Поэтому `CLAUDE.md`, навык в `.claude/skills/` и промпты в `prompts/` —
> часть результата, а не служебные файлы: понятные, по-русски, без воды.»

> «**Регулярный запуск** — не разовый анализ: одна команда пересчитывает всё
> по обновлённым данным (ежедневно или по запросу) и показывает, что изменилось
> с прошлого запуска.»

> «**Пояснения (ИИ).** Для строк «заказать сейчас» и «риск» — 1–2 предложения
> закупщику (почему, что учтено: сезон, в пути, надёжность) + общая сводка
> на 5–7 строк по всему плану. Вызов через OpenAI-совместимый API
> (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` из `.env`). Нет ключа или ошибка —
> шаблонное пояснение из цифр, расчёт от этого не зависит. Промпт — в
> `prompts/explain.md`. В промпт идут только цифры и id, без лишнего.»

> «Одна статичная HTML-страница (`out/dashboard.html`), открывается без сервера,
> данные внутри, графики — одна библиотека с CDN (Plotly или Chart.js).
> - шапка: дата данных, сколько SKU заказать сейчас / запланировать / риск / избыток /
>   низкая наценка / мёртвые; штук к заказу всего;
> - главная таблица «Что заказать»: SKU, категория, поставщик, статус, сколько,
>   до какой даты, покрытие (мес.), в пути, плечо, пояснение. Сортировка, фильтр по
>   категории и статусу, поиск по SKU, выгрузка в CSV;
> - календарь заказов: по месяцам на 12 мес — сколько позиций и штук разместить;
> - риски: дефицит (с месяцами «дыры»), избыток, просроченные заказы поставщиков;
> - отдельные списки: низкая наценка, мёртвый ассортимент;
> - по клику на SKU — график: история спроса, прогноз, остаток в симуляции, приходы;
> - сезонность категорий (12 месяцев, доли);
> - блок «Что изменилось с прошлого запуска»;
> - сводка ИИ сверху.
> Мобильная ширина не обязательна, но таблица не должна ломаться.»

> «- `python -m zakupki run --data data/raw/share --today 2026-08-13` → `out/`
>   (dashboard.html, plan.csv, risks.csv, summary.md) + снимок в `out/history/<дата>/`;
> - сравнение с предыдущим снимком → «что изменилось» (новые к заказу, сдвинулись
>   даты, ушли из риска);
> - `scripts/run_daily.ps1` (Windows Планировщик) и пример cron / GitHub Actions;
> - `README.md`: как обновить данные и запустить, 10 строк.»

> «`CLAUDE.md` в корне: что за проект, как устроен, как запускать, правила
> (цифры — только код, пороги — в конфиге). Навык `.claude/skills/plan-zakupok/SKILL.md`:
> как запустить анализ, как читать результат, как поменять параметры.»

> «Никаких следов «сгенерировано ИИ» в комментариях. Комментарии по-русски, коротко.»
